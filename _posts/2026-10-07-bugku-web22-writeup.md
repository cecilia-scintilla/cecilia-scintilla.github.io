Bugku CTF - 矛盾 Writeup

一、题目信息

- 题型：WEB
- 题目：矛盾
- 考点：PHP 弱类型比较（`==` 的隐式类型转换）、`is_numeric()` 与 `==` 的判定差异

二、题目分析

- 启动场景后打开页面，能看到一段 PHP 源码：

```php
$num = $_GET['num'];
if (!is_numeric($num)) {
    echo $num;
    if ($num == 1)
        echo 'flag{**********}';
}
```

- 需求拆解一下，要输出 flag 必须同时满足两个条件：

```text
条件1:  !is_numeric($num)   ->  $num 不能是"数字"
条件2:  $num == 1           ->  但 $num 又要"等于 1"
```

- 字面上这两条是**矛盾的**（题目名字就是这么来的）：既然是数字才能等于 1，那就不可能不是数字。
- 突破口在于：**`is_numeric()` 和 `==` 是两套完全不同的判断逻辑**。
  - `is_numeric($num)` 要求**整个字符串**都是合法的数字格式，`"1a"`、`"1!"` 都会被判定为"不是数字"；
  - `==` 是**弱类型比较**，两边类型不同时 PHP 会做**隐式类型转换**：把字符串转成数字时，**只取开头的数字部分，后面的字符直接忽略**。

三、解题步骤

- 构造 payload：让 `num` 以数字 `1` 开头，但整体不是合法数字。例如 `1a`：

```text
?num=1a
```

- 两条判断的走向：

```text
is_numeric("1a")  ->  false   ->  !false = true   ✅ 通过
"1a" == 1         ->  PHP 把 "1a" 转成 1，1 == 1  ->  true  ✅ 通过
```

- 完整请求（把场景地址换成你自己的）：

```text
http://<题目地址>/?num=1a
```

- 页面上就会回显 flag。**本题的 flag 是每个环境独立的**（32 位十六进制），所以要提交你自己页面上看到的那个，不能抄别人的。
- 换个 payload 也一样有效，原理相同（数字开头 + 后面跟非数字字符）：

```text
?num=1a      ?num=1!      ?num=1abc      ?num=1%00
```

四、总结

- 核心知识点是 **PHP 弱类型比较**，这是 CTF 里 WEB 方向的高频考点，记住三点：
  1. `==`（松散比较）在类型不同时会**自动类型转换**再比较；`===`（严格比较）要求**类型和值都相同**；
  2. 字符串与数字比较时，PHP（7.x）**只取字符串开头的数字部分**，`"1a" == 1` 为真、`"abc" == 0` 也为真；
  3. `is_numeric()` 检查的是**整个字符串**的格式，和 `==` 的转换规则不一致 —— 这个"不一致"就是所有此类绕过题的根源。
- 常见的弱类型绕过手段（扩充知识面）：
  - 数字开头 + 非数字字符：`1a`、`1!`（本题）；
  - 科学计数法绕过：`1e3`、`0e123456` —— 后者常用于"两个 md5 值比较相等"的题（`0e` 开头的哈希在 PHP 里会被当成 0）；
  - 数组绕过：`?num[]=1` —— 数组与数字比较永远为假，但 `is_numeric(数组)` 报错/为假，可绕过某些强类型判断；
  - `%00` 截断：老版本 PHP 的经典手法（PHP 5.3.4+ 已修复大部分场景）。
- 一个重要提醒：**PHP 8 起行为变了**。PHP 8 中 `"abc" == 0` 为 **false**（不再把非数字字符串转成 0），但 `"1a" == 1` 依然是 **true**（数字开头的字符串仍会转换）。所以本题用 `1a` 在 PHP 8 下同样能绕，但"纯字符串转 0"那类技巧在新版本上就失效了 —— 做老题时要注意环境版本。
