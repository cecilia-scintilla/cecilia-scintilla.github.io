浏览器开发者工具（F12）完全指南 —— CTF 与安全测试必备

这篇整理了 F12（开发者工具 / DevTools）常用的功能和快捷键，重点讲**做 CTF Web 题时怎么用**。

一、F12 是什么，和 Burp 有什么区别

```text
F12 打开的是「浏览器开发者工具」(DevTools) —— 浏览器自带，不用装任何东西

它和 Burp 的分工：
    Burp  → 看/改「请求和响应」（网络层：方法、请求头、参数）
    F12   → 看/改「网页本身 + 浏览器存储」（页面层：HTML、JS、Cookie）
```

**什么时候用哪个**：

| 需求 | 用 F12 | 用 Burp |
|---|---|---|
| 看网页源码 / HTML 结构 | ✅ 最方便 | 也能看，但费劲 |
| 看/改 JS 逻辑 | ✅ 唯一选择 | ❌ 很难 |
| 搜页面里的 flag | ✅ `Ctrl+Shift+F` 全局搜 | ❌ |
| 改 Cookie 的值 | ✅ **改完刷新即生效** | 也行，但要拦截 |
| 改请求头（UA / Referer / XFF） | ❌ **改不了** | ✅ 唯一选择 |
| 改请求方法（GET→POST→CTFHUB） | ❌ | ✅ |
| 看 302 的原始响应 | ⚠️ 会自动跟随，看不到 | ✅ Repeater 原样显示 |
| 反复改参数重发 | ❌ 得重新操作页面 | ✅ Repeater |
| 爆破 | ❌ | ✅ Intruder |

**一句话记法**：
- 改「页面里存的东西」→ **F12**
- 改「发出去的请求」→ **Burp**

二、六个标签页都是干什么的

| 标签 | 中文 | 主要用途 |
|---|---|---|
| **Elements** | 元素 | 看/改页面 HTML 和 CSS（看结构、改内容、绕过前端校验） |
| **Console** | 控制台 | 执行 JavaScript（弹窗测试、解码、看变量） |
| **Network** | 网络 | 看所有请求（URL、参数、响应、状态码、响应头） |
| **Application** | 应用程序 | 看/改 Cookie、LocalStorage、SessionStorage |
| **Sources** | 源代码 | 看 JS/CSS 文件、断点调试 |
| **Security** | 安全 | 看 HTTPS 证书信息 |

做 CTF 题常用的是前四个。

三、⭐ 五个最有用的功能（配 CTF 场景）

**① 看网页源代码（"响应包源代码"这类题）**

```text
方法 A：右键页面 → "查看网页源代码"（快捷键 Ctrl+U）
方法 B：F12 → Elements 标签
```

⚠️ **两者看到的可能不一样，这点很关键**：

```text
Ctrl+U       → 服务器返回的【原始 HTML】（未经 JS 处理）
Elements     → 浏览器解析后的【渲染结果 DOM】（可能已被 JS 增删改）

所以：如果 flag 藏在"被 JS 删掉的标签"里，
     必须用 Ctrl+U 看原始源码，Elements 里已经看不到了
```

**② 看/改 Cookie（"Cookie 伪造"这类题）**

```text
F12 → Application 标签 → 左侧 Storage 里找 Cookies → 展开题目域名
→ 看到 admin=0 → 双击那个值改成 1 → F5 刷新页面 → flag 出现
```

比 Burp 快得多 —— 因为改完刷新就生效，不用折腾拦截开关。

**③ 看所有网络请求（Network）**

```text
F12 → Network 标签 → 刷新页面（或点页面上的按钮）
→ 列表显示每个请求：Name / Status / Type / Size / Time
→ 点任意一条 → 右侧有几个子标签：
      Headers   → 请求头 + 响应头（看 Set-Cookie、Location、自定义头）
      Payload   → 提交的参数（POST 的表单数据）
      Preview   → 美化后的响应
      Response  → 原始响应内容
```

**用途**：
- 找**隐藏的接口**（页面上没显示、但被 JS 调用的 API）
- 看登录/提交到底发了什么参数
- 看响应头里的 `Set-Cookie`、`Location`

⚠️ **F12 的 Network 和 Burp 的一个重要区别**：F12 **也会自动跟随 302 跳转**，你只能看到跳转后的请求（除非提前开着 F12 并勾选 **Preserve log**）。所以**看 302 还是用 Burp 更稳**。

**④ Console 执行 JavaScript**

在 Console 里可以直接敲 JS 并立刻执行：

```javascript
// 看当前页面的 Cookie（HttpOnly 的看不到）
document.cookie

// 看页面完整的 HTML（包括被 CSS 隐藏的内容）
document.body.innerHTML

// XSS 题测试有没有漏洞
alert(1)

// 顺手做编码解码
atob("Y3RmaHVi")      // Base64 解码 → ctfhub
btoa("ctfhub")        // Base64 编码 → Y3RmaHVi

// 看页面上所有表单的隐藏字段
document.forms
```

**实用场景**：有些题前端做了校验（"密码必须等于 xxx 才能提交"），可以直接在 Console 里改掉那个校验变量，或者调用页面内部函数绕过。

**⑤ 全局搜索（很多人不知道）**

```text
F12 打开后按 Ctrl + Shift + F
→ 可以在【所有 JS / HTML / CSS 文件】里全局搜索
→ 比如直接搜 "flag"、"password"、"key"
```

有些题的 flag 藏在某个 **JS 文件**里（页面上不显示），用这个一搜就出来。

四、⚡ 快捷键速查

| 快捷键 | 作用 |
|---|---|
| `F12` 或 `Ctrl+Shift+I` | 打开/关闭开发者工具 |
| `Ctrl+Shift+C` | **点选元素**（鼠标指哪看哪，用来定位页面上某个东西的代码） |
| `Ctrl+Shift+J` | 直接打开 Console |
| **`Ctrl+U`** | 查看网页源代码（**原始 HTML**，注意和 Elements 的区别） |
| **`Ctrl+Shift+F`** | 在 DevTools 里全局搜索（搜所有源文件） |
| `Ctrl+Shift+M` | 切换手机模拟（**伪装手机 UA** 访问） |
| `Ctrl+R` / `F5` | 刷新页面 |
| `Ctrl+Shift+R` | 强制刷新（忽略缓存，**调试时很有用**，避免看到旧内容） |

五、CTF 里 F12 的典型用法清单

```text
① 响应包源代码题   → Ctrl+U 看源码，或 Ctrl+Shift+F 搜 flag
② Cookie 题        → Application 里改 admin=0 → 1
③ 前端校验绕过     → Elements 里删掉 disabled / 改 maxlength / 改隐藏字段的值
④ 找隐藏接口       → Network 里看有没有页面上没显示的请求
⑤ flag 藏在 JS 里  → Sources 翻 JS，或 Ctrl+Shift+F 全局搜
⑥ XSS 验证         → Console 里 alert(1) 看弹不弹
⑦ 伪装手机访问     → Ctrl+Shift+M 切换设备模拟（改 UA）
⑧ 看被隐藏的内容   → Elements 里找 display:none 的元素，或在 Console 里读 innerHTML
```

六、和 Burp 配合的完整工作流

做一道典型的 Web 题，两个工具的配合顺序通常是：

```text
① F12 → Network  先看这题有哪些请求、有没有可疑接口
② F12 → Elements / Ctrl+U  看页面源码有没有提示、注释、隐藏字段
③ F12 → Application  看 Cookie 里有没有身份相关的值（admin、role、user_id）
④ 如果漏洞在【页面/Cookie 层】→ 直接用 F12 改，刷新看结果
⑤ 如果漏洞在【请求层】（改方法/头/参数）→ 开 Burp 拦截，或发到 Repeater 反复试
⑥ 需要爆破 → Burp 的 Intruder
```

七、几个容易被忽略的实用细节

**① 有些网站会禁用 F12**

```text
现象：按 F12 没反应，或弹出"禁止使用开发者工具"
原因：前端用 JS 检测了按键（比如监听 keyCode 123）
绕过：
    · 用浏览器菜单打开：右上角 ⋮ → 更多工具 → 开发者工具
    · 或者直接在 Burp 里分析请求（Burp 不受这个限制）
注意：这种"禁用"只是障眼法，前端代码改不了服务端行为，
     真正要看请求内容，Burp 永远能看到
```

**② "改页面"只影响你自己的浏览器**

在 Elements 里改 HTML/CSS、在 Console 里改 JS 变量，**都只在你本地生效**，刷新就没了，也不会影响服务器。所以：

```text
✅ 可以用来绕过"只做在前端"的校验（因为绕过发生在你这边）
❌ 不能用来"真的改掉服务器上的东西"（那需要从请求层动手）
```

**③ 缓存经常坑人**

改完东西发现没变化？先试 **`Ctrl+Shift+R`（强制刷新）** —— 浏览器可能用了缓存的旧文件。

**④ Application 里还能看别的**

```text
Cookies          身份凭证（最常用）
Local Storage    网站存在本地的键值对（有些题把 flag 放这儿）
Session Storage  标签页级别的临时存储
Cache Storage    Service Worker 缓存的文件
```

八、总结

- **F12 是浏览器自带的"透视镜"**：让你看到网页的真实结构、执行 JS、查看和修改浏览器存储的所有东西。
- **记住核心分工**：改页面/存储用 **F12**，改请求用 **Burp**。
- 三个最该记住的快捷键：**`Ctrl+U`**（原始源码）、**`Ctrl+Shift+F`**（全局搜）、**`Ctrl+Shift+M`**（手机模拟）。
- 一个必须理解的区别：**Elements 看到的是"渲染后"的页面，Ctrl+U 看到的是"服务器原始返回"** —— 有些题的答案只存在于后者。
- 最后提醒：F12 能看到/改到的都只是**客户端的东西**，真正的安全边界在服务器。理解了这一点，就能明白为什么"前端校验不算校验"、为什么"信任客户端数据"是漏洞。
